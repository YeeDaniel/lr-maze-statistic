# 遺跡 LV6 遺物紀錄工具 · 設計文件

日期：2026-08-05　｜　狀態：待實作

把現有的 `lv6-relic-scores.html`（單檔、資料硬編碼）改成別人也能用的工具：各自輸入自己的紀錄、存在自己的瀏覽器、不做任何同步。

---

## 一、目標與非目標

### 目標

- 任何人打開網址就能輸入自己的 LV6 紀錄，資料存在自己的裝置
- 手機為主要使用情境，桌機為輔
- 保留現有的四塊分析：各趟總覽、每關走勢（三模式）、每輪明細、分數分布
- 內建作者的 6 趟紀錄當唯讀基準線，新使用者一打開就有對照組
- 可匯出備份、可匯入朋友的紀錄來比較

### 非目標

- **不做帳號、不做後端、不做同步**。資料只在瀏覽器
- **只做 LV6**。關卡序列寫死，不支援其他難度
- 不做 PWA／離線安裝（之後要加不會衝突）
- 不做遺物同分的使用者自訂釐清（`TIEBREAK` 維持現有內建做法）

## 二、決策紀錄

| 項目 | 決定 | 理由 |
|---|---|---|
| 架構 | 原生 ES module 多檔，**無建置** | 走 GitHub Pages 後「單檔好丟」失去意義；不裝 npm 就沒有建置維護成本 |
| 樣式 | 沿用現有手寫 CSS | CSS 變數、深色模式、中文排版都調好了。Tailwind 需要 build，與無建置衝突 |
| 圖表 | 維持 Chart.js | 折線／長條／散點都夠用。amCharts 免費版帶 logo、商用要授權，且強項（地圖、桑基圖）用不到。熱力圖若要做，CSS grid 手刻比裝庫簡單 |
| 發布 | GitHub Pages | 手機為主，本地 HTML 檔在 iOS 上開不起來也存不活 localStorage |
| 內建資料 | 作者 6 趟當唯讀基準線 | 新使用者一打開就有東西看、有對照組 |
| 平均基準 | 只算使用者自己的趟數 | 「跟自己比」比「跟作者比」有意義 |
| 輸入方式 | 分數為主，類型/屬性用 chip 補 | 分數是玩家在遊戲畫面唯一直接看得到的數字，手機打 4 位數最快 |

## 三、檔案結構

```
lr-maze-statistic/
├── index.html            版面骨架 + 兩個分頁（統計／我的紀錄）
├── .nojekyll             GitHub Pages 不跑 Jekyll
├── css/
│   ├── base.css          CSS 變數、深色模式、中文排版（自現有 HTML 搬出）
│   └── app.css           版面與元件樣式
├── js/
│   ├── config.js         PROG / STAGE / FRONT / BONUS / MULT（LV6 常數）
│   ├── official.js       官方 437 顆分數表 + 效果權重（自現有 HTML 搬出）
│   ├── baseline.js       作者 6 趟，唯讀
│   ├── decode.js         分數 → 級距 / 正負 / 目標類別 / 候選遺物
│   ├── stats.js          純函式：小計、總分、平均、累積差、分組統計
│   ├── store.js          localStorage 讀寫、schema 版本、匯出匯入
│   ├── view-chart.js     折線圖
│   ├── view-detail.js    每輪明細表
│   ├── view-dist.js      分數分布
│   ├── view-entry.js     輸入／編輯表單
│   ├── view-manage.js    趟次清單、匯出匯入
│   └── main.js           state + render 調度
├── vendor/chart.umd.js
├── tests/run.mjs         node 原生跑，零依賴
└── docs/superpowers/specs/
```

全部用相對路徑（`./js/main.js`），GitHub Pages 專案站的子路徑自動成立，不需要設定 base。

### 模組邊界

| 模組 | 職責 | 依賴 |
|---|---|---|
| `config.js` | LV6 靜態常數 | 無 |
| `official.js` | 官方遺物資料，唯讀 | 無 |
| `decode.js` | 分數 → 結構化遺物資訊。**唯一懂計分公式的地方** | `official.js` |
| `stats.js` | 純函式統計。無 DOM、無 I/O | `config.js` |
| `store.js` | 持久化與序列化。無 DOM，不認識 `builtin` | `config.js` |
| `view-*.js` | 各自 `mount(el)` / `update(state)`，**互不呼叫** | `decode.js`、`stats.js` |
| `main.js` | 合併 `baseline` 與 store 的資料成 state、訂閱 store 變動、呼叫各 view 的 `update` | 全部 |

現有程式碼把 `MEAN` / `CUM` / `chart` 都在載入時算一次
（`lv6-relic-scores.html:178-183`、`:231`）。改成 store 變動 → `main.js` 重算 state → 各 view `update(state)`。

## 四、資料模型

```js
// localStorage key: "lr-maze-lv6/v1"
{
  v: 1,
  runs: [{
    id: "r_1754384000000",
    name: "LV6 7th",
    note: "75% 開始坐牢",
    origin: "mine" | "imported",
    from: "朋友A",                    // 只有 imported 有
    createdAt: "2026-08-05T03:20:00.000Z",
    cells: [                          // 固定長度 20，index 對應 PROG
      { score: 342, target: "力" },   // target 可為 null（未選）
      // ...
      { score: 0, target: null }      // index 19：100% 魔王兔兔，固定無遺物
    ]
  }]
}
```

### 與現有格式的差異

現有是 `s:[分數...]` + `r:['負C敏'...]` 兩個平行陣列。新模型**只存分數與目標，級距／正負／類型-屬性一律由 `decode.js` 從分數推導**。

好處是資料永遠自洽 —— 不可能再出現 md 第五節修正過的「分數 1070 卻標成負B敏」那種不一致（1070 只存在於 B 級負向屬性）。修正一筆紀錄只需改 `target` 一個字。

`baseline.js` 由現有 `RUNS` 一次性轉檔。

### 三種資料來源

| origin | 來源 | 畫在圖上 | 計入平均 | 可編輯 | 可匯出 |
|---|---|---|---|---|---|
| `builtin` | 作者 6 趟，寫在 `baseline.js` | 是，可隱藏 | 否 | 否 | 否 |
| `mine` | 使用者自己輸入 | 是 | **是** | 是 | 是 |
| `imported` | 匯入朋友的 | 是，可隱藏 | 否 | 只能刪 | 否 |

`builtin` 不進 localStorage，每次由程式碼載入。

### 平均基準規則

- `mine` 趟數 ≥ 2 → 平均只算 `mine`
- `mine` 趟數 < 2 → 退回內建 6 趟，圖上標注「基準：內建 6 趟 · 你滿 2 趟後改用自己的」
- `imported` 永不計入平均

「與平均差距」「累積差距」兩個模式都吃這個基準。

## 五、decode.js

輸入分數，輸出：

```js
{
  grade: "A" | "B" | "C",
  sign: "負" | "正",
  kind: "類型" | "屬性",
  candidates: ["腐爛的尾巴", "感染的樹液", "詛咒的咒文書"],  // 同分則多筆
  ok: true                                                   // 官方表查得到
}
```

查無此分數時回傳 `{ ok: false }`。

### 唯一性前提

十二組分數帶完全不重疊，因此分數可唯一決定 `grade` / `sign` / `kind`：

| 級距 | 正向·類型 | 正向·屬性 | 負向·屬性 | 負向·類型 |
|---|---|---|---|---|
| C | 240–264 | 270–282 | 311–321 | 330–360 |
| B | 770–880 | 885–940 | 1,035–1,077 | 1,100–1,220 |
| A | 1,694–1,936 | 1,947–2,068 | 2,277–2,369 | 2,420–2,684 |

注意「正向·類型」在作者的六趟實測中從未出現（md 第六節第 3 點），但官方表有這 25 筆分數，其他玩家抽得到，`decode` 必須認得。

分數推不出來的只有「力／敏／智哪一個」或「火／水／木／光／暗哪一個」—— 公式裡目標種類不影響分數（C 級類型一律 `3j`，正向屬性一律 `150+1.5j`）。這部分由使用者用 chip 補。

**這個不重疊性是整個輸入 UX 的前提，必須由測試驗證**（見第九節第 1 條）。若驗證失敗，輸入方式必須改成完整下拉選單。

## 六、輸入流程

分頁「我的紀錄」→ 趟次清單 + 「新增一趟」。

表單：名稱（自動帶 `LV6 7th` 遞增）、備註一行、20 關列表。

每一關的互動：

```
75%  雙線     [ 2596 ]   A · 負向 · 類型
                         (力) (敏) (智)
```

1. 分數欄 `inputmode="numeric"`，打完即時呼叫 `decode`
2. 右側徽章顯示 `A · 負向 · 類型`
3. 下方 chip 換成對應選項：`類型` → 力/敏/智；`屬性` → 火/水/木/光/暗
4. chip 不選也能存，只是分屬性的統計會缺角

### 版面

- 手機：一關一張卡，選完 chip 自動捲到下一關，可以邊玩邊記
- 桌機：20 列表格一次看完
- 同一份 DOM，CSS breakpoint 切換，不做兩套

### 邊界

- index 19（100% 魔王兔兔）分數鎖 0、不可編輯、無 chip
- 分數查無此值 → 紅框提示「官方表沒有這個分數」，**警告但不阻擋**
- 隨打隨存草稿到獨立 key `lr-maze-lv6/draft`，手機切換 App 再回來不會掉。存檔成功後清掉草稿
- chip 選項不預先限制正面關只給屬性 —— md 第六節那是「待確認事項」而非已確認規則，寫死就永遠驗證不了

## 七、匯出／匯入

### 匯出

只含 `origin === "mine"` 的趟，不轉手散播別人的資料。兩個動作：

- **複製到剪貼簿**（手機主力）
- **下載 .json**（桌機）

### 匯入

先問來源：

- **自己的** → 併進 `mine`，計入平均
- **朋友的** → 標 `imported` + 填來源名，不計入平均

驗證項目：`v` 版本相容、`runs` 為陣列、每趟 `cells` 長度為 20、`score` 為數字。任一項失敗即拒絕，訊息指出壞在哪一趟哪一格。

同 `id` 已存在 → 詢問覆蓋或當作新的一趟（產生新 id）。

## 八、錯誤處理

| 狀況 | 行為 |
|---|---|
| localStorage 被禁（無痕模式） | 頂部橫幅：「這個瀏覽器不讓存資料，關掉頁面就沒了」。功能照常可用 |
| 存檔 JSON 解析失敗 | **不清空**。備份到 `lr-maze-lv6/v1.broken`，載入空狀態並告知使用者 |
| 存檔 `v` 大於程式支援版本 | 拒絕載入，提示重新整理取得新版 |
| localStorage 寫入失敗（配額滿） | 橫幅告知，提示先匯出備份 |
| 分數對不上官方表 | 紅框警告，不阻擋儲存 |

## 九、測試

`tests/run.mjs`，node 原生執行（`node tests/run.mjs`），零依賴。純函式模組（`decode` / `stats` / `store` 的序列化部分）可直接 import。

1. **分數帶不重疊** —— 十二組（3 級距 × 正負 × 類型/屬性）的分數區間兩兩不相交。**先寫這條**，它是輸入 UX 的前提
2. **decode 正確性** —— 官方 437 筆逐一丟回 `decode`，`grade` / `sign` / `kind` 全對
3. **公式一致性** —— 用 md 第 2.2 節公式重算 437 筆，與官方表比對
4. **stats 回歸** —— `baseline.js` 6 趟算出的總分須為 132,195 / 132,760 / 134,225 / 135,475 / 134,595 / 133,285
5. **store round-trip** —— 存讀往返、匯出匯入、壞資料被拒絕
6. **平均基準切換** —— `mine` 為 0 / 1 / 2 趟時，平均分別取自內建、內建、自己的
